# Живой уголок — бэкенд

ASP.NET Core Minimal API + Dapper + SQLite.

## Запуск в Райдере

1. Создай пустое решение, добавь существующий проект `LivingCorner.Api.csproj` (или просто открой папку).
2. Если у тебя не .NET 8, поменяй `net8.0` в `.csproj` на свою версию (и версию `Microsoft.Data.Sqlite` на такую же мажорную).
3. Нажми Run. Откроется/станет доступен `http://localhost:<порт>/swagger` — там можно тыкать все запросы без фронта.
4. БД `livingcorner.db` создастся сама рядом с проектом при первом запуске. Чтобы сбросить всё — удали этот файл.

|Персонажі акаунта|`GET /api/users/{id}/persons`|
|Зарегистрироваться (персонаж)|`POST /api/register` `{name, day, month, year, userId?}`|
|Данные игрока (баланс, статус)|`GET /api/persons/{id}`|
|Мертвые|`GET /api/dead`|
|В ожидании|`GET /api/waiting`|
|Похоронить (убрать из ожидания)|`POST /api/waiting/{personId}/bury`|
|Заказы|`GET /api/orders`|
|Магазин (список)|`GET /api/shop`|
|Купить заранее|`POST /api/shop/buy` `{personId, coffinId, tierId, priestId}`|

## Правила игры (константы вверху `Program.cs`)

* Поле 3x3, в 2 ямах пёс патрон. Позиции псов фронту не отдаются.
* 10 валюты за яму. Выкопал все 7 безопасных - игра кончается, приз 90 (как за 9 псов).
* Взрыв → статус `Exploded` → воскрешение (100), платная смерть (цена уровня) или бесплатная.
* Смерть записывает сегодняшнюю дату как дату смерти и случайный морг.

## Уровни

1 Бесплатный (0), 2 Обычный (500), 3 Премиум (2000). Цены гробов/священников/уровней — в `Db.cs`.

## Акаунти та безпека

* Таблиця `Users`: Id, Login (унікальний індекс, без урахування регістру), PasswordHash, FirstName, LastName, Email, RegisteredAt.
* Пароль зберігається лише як хеш PBKDF2-SHA256 (210 000 ітерацій) з випадковою сіллю. Відкритого пароля немає ні в БД, ні в коді.
* Валідація: логін >= 3, пароль >= 6, паролі збігаються, email (необов'язковий) коректний, обов'язкові поля не порожні.
* Дублікат логіна -> 409 і зрозуміле повідомлення, у БД не зберігається.
* Помилка входу завжди `Невірний логін або пароль` (401), без підказки, що саме не так.
* Після успішної реєстрації фронт повертає користувача на форму входу; головна форма відкривається лише після успішного `login`.
* **Якщо БД створена до цього оновлення, видали `livingcorner.db`**: з'явилась нова таблиця і колонка.
